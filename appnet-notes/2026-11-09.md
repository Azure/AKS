## AppNet Release Notes - 2026-11-09

> [Azure Kubernetes Application Network (AppNet)](https://learn.microsoft.com/azure/application-network) — release changes after August 10 through November 9, 2026. AppNet is in public preview. Version and channel availability varies by region and AKS Kubernetes version; see [supported versions](https://learn.microsoft.com/en-us/azure/application-network/supported-versions#supported-application-network-versions-and-compatible-aks-versions).

### Announcements and retirements

* AppNet 1.3 (Istio 1.28) has been retired. Members using this version in self-managed upgrade mode should upgrade to a supported AppNet version compatible with their AKS cluster, following the [AppNet upgrade guide](https://learn.microsoft.com/en-us/azure/application-network/upgrades#initiate-an-upgrade).
* AppNet patches 1.4.0–1.4.8, 1.5.0–1.5.5, and 1.6.0–1.6.1 have been retired.

### Features

* AppNet is now available in public preview in four additional Azure regions: Canada Central, Central India, Sweden Central, and West US. See the [supported regions](https://learn.microsoft.com/en-us/azure/application-network/overview#limitations).
* AppNet now supports single-network multicluster connectivity. Members using the same network name can communicate directly through the ambient data plane when their non-overlapping pod IP ranges are reachable in both directions. East-west gateways are bypassed for this traffic; gateway provisioning is unchanged. See [configure multicluster connectivity](https://learn.microsoft.com/en-us/azure/application-network/multi-cluster-connectivity).
* AppNet now supports onboarding eligible private AKS clusters through private connectivity. This requires service enablement and the `Microsoft.AppLink/PrivatePath` feature to be in the `Registered` state on the subscription containing the AppNet member resource before joining. Learn how to [connect private AKS clusters to AppNet](https://learn.microsoft.com/en-us/azure/application-network/private-connectivity).

### Bug fixes

* Fixed an issue where reapplying an unchanged ARM template to a self-managed AppNet member without an explicitly pinned version could initiate an unexpected upgrade to the default minor version. The member now preserves its current AppNet version even if the version field is left empty.
* Fixed incorrect version-transition validation after a self-managed version update failed. Validation now uses the last successfully provisioned version, and existing members can continue reconciling an unchanged running version even if that version later becomes unsupported.
* Fixed an issue where deleting a failed member could unintentionally remove an AKS cluster's active AppNet membership if the same cluster had been used in a second AppNet join attempt. The active membership is now preserved.
* Fixed AppNet cascading member deletion and an AKS/AppNet reconciliation loop that could prevent cluster deletion from completing.
* Fixed issues that could leave AppNet operations or member joins pending indefinitely, including failures during provisioning and routine infrastructure maintenance. Unrecoverable operation failures now complete with an error so they can be retried.
* Deleting an AppNet resource or member while its creation or update is still in progress now returns clear retry guidance instead of starting a conflicting deletion.
* Fixed an issue that could prevent AppNet member provisioning or upgrades when an AKS cluster restricts API-server access to approved IP addresses.
* Improved provisioning and upgrade reliability for healthy members when another member cluster's API-server DNS cannot be resolved. Reconciliation resumes automatically when that member becomes reachable.
* Fixed metrics-proxy readiness issues that could make AppNet control-plane metrics unavailable or block upgrades when a linked AKS cluster is unavailable or deleted.
* AppNet mesh components, including ztunnel and istio-cni, are no longer scheduled onto virtual nodes, where they could remain stuck in Pending or CrashLoopBackOff.
* Improved provisioning retry and deletion reliability by preserving existing allocations and reporting cleanup failures instead of silently leaving capacity reserved. Failed creations that require recreation now provide clear delete-and-recreate guidance.

### Component updates

* Published the `2026-11-01` stable API specification. It adds the read-only `connectivityProfile.controlPlaneFqdn` property, exposing an AppNet member’s managed control-plane hostname. Public API availability is unchanged.
* AppNet 1.4 has been updated to [Istio 1.29.10](https://istio.io/latest/news/releases/1.29.x/announcing-1.29.10/).
* AppNet 1.5 has been updated to [Istio 1.30.7](https://istio.io/latest/news/releases/1.30.x/announcing-1.30.7/) and promoted to the stable channel.
* AppNet 1.6 is now available on the rapid channel, using [Istio 1.31.3](https://istio.io/latest/news/releases/1.31.x/announcing-1.31.3/).
* AppNet 1.5 and 1.6 now support AKS Kubernetes 1.37.
* The latest AppNet patches include optimized control-plane and data-plane builds.
